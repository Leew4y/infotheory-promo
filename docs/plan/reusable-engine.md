# 计划：从一部片子到可复用的 demo 视频引擎

状态：草案 r2（已按第一轮 Codex 评审修订）· 2026-10-03

## 目标

一个引擎做很多部 hackathon 项目的 demo 演示视频：风格有辨识度、美观，可在多套风格之间切换。
生产方式是人用自然语言描述，coding agent（Claude Code / Codex）整理输入、生成分镜与场景、渲染、自检、修改。
远期目标是端到端批量生成不同主题的片子；本计划的终点是：**第二部片子从 brief 做到成片，不修改 `engine/`，也不复制第一部的内部硬编码。**

协作环境：Windows + macOS，两人。

## 已定的方向

- **保留现有渲染内核**（Canvas2D + WebGL2、`frame(t)` 纯函数、headless Chrome 精确帧、ffmpeg），前提是阶段 0 的决策门通过。
  Revideo（MIT，0.11.0）是备选。Remotion 不作为核心：它使用自定义许可（当前 LICENSE.md 对个人、≤3 名员工的营利组织、非营利组织免费，其余需公司许可；5.0 条款待生效），
  我们更想要宽松许可且保留现有 WebGL 管线。
- **IR 先行，代码后生成**：agent 先写结构化中间产物，经校验后再生成或修改场景代码。agent 决定"想做什么"，编译器和校验决定"什么是合法的"。
  IR 的 schema 在哪个阶段交付、由谁消费，见下文各阶段的"契约"一栏。
- **不自建 agent 运行时**：agent 就是 Claude Code / Codex。仓库提供的是接口：输出 JSON 的 `just` 命令、Zod schema、AGENTS.md、项目 skill。
- **旁白是 demo 片的默认主时钟**，但场景时长取 `max(旁白 + 留白, 必须展示的素材段)`；节拍网格降为风格包里的可选项。
- **生产渲染不使用系统字体**：OFL 字体随仓库分发，CJK 按片子子集化，并校验实际文本的字形覆盖。
- 继续用 bun / vite / uv / just；不改成 Rust，不引入 mise。

## 非目标

自建 agent 运行时或工具协议；迁移到 Remotion；生成式音乐替代程序化配乐；Windows 与 macOS 输出字节一致；
从参考视频自动提取风格；完整的非线性编辑 GUI；一次建很多套风格；批量调度。

## 全局契约

这些规则从阶段 1 起生效，后续阶段只扩展、不推翻。

- **时间**：权威单位是影片帧号（整数，`fps` 由 film 声明）。场景时长以秒声明，解析时取整到帧；场景区间半开 `[start, end)`；
  片尾 tail 是 film 的独立字段，不计入任何场景的 `len`。解析结果写成 `timeline.json`，TS 渲染和 Python 配乐都只读它。
- **子帧与素材帧**：运动模糊的子帧只影响镜头、矢量绘制和叠加层；视频素材的源帧号只由输出帧号决定（每个输出帧对应唯一源帧），不随子帧变化。
- **色彩**：工作空间是 sRGB 编码值，混合也在 sRGB 编码值上进行（保持现有外观）；成片标记 BT.709、limited range，ffmpeg 转换参数显式写出。
  改用线性空间混合属于视觉变更，不在本计划内。
- **诊断**：所有校验类命令输出 `{ level, code, path, message }` 列表；有 error 时退出码非零。
- **产物**：任何改名为正式文件的成片，必须先通过帧数、时长、音轨存在且不短于视频的检查。

## 阶段与验收

每个阶段写明输入、命令、产物、退出条件、失败用例。每个阶段一到数个 PR。

### 阶段 0 · 验证（本 PR，不改 `src/`、`scripts/`、`audio/`）

实验代码放 `spikes/`，各自独立。结果写入 `spikes/RESULTS.md`，含机器、操作系统、Chrome、GPU 后端、ffmpeg 版本。
参考机器：Windows 11、RTX 3060 Laptop、Chrome（ANGLE D3D11）。参考片长：90 秒 demo。

**0a · 基线确定性。**
在 `421b107` 上，通过现有导出钩子渲染后再取 canvas 的**无损 PNG**（不比较 JPEG）。
覆盖：冷启动两次、同一组时刻正序与乱序、重复 seek 同一时刻、1 个与 4 个 worker、每个场景边界的前后各一帧。
退出条件：所有组合逐像素一致。失败时定位非确定性来源，阶段 1 的回归标准据此调整。

**0b · 录屏素材嵌入。**
测试素材：ffmpeg 生成 90 秒 1080p30 视频，每帧含可见的帧号条码，另含灰阶、色块、细字样片。预先拆成固定帧率的图片序列（PNG 与 JPEG q95 各一份）。
最小场景按输出帧号取源帧，按需加载并使用有上限的缓存（不全量解码；全量 RGBA 约 21 GiB/worker，不可行）。
分开验证：
1. 源帧选择：关闭运动模糊，每个输出帧解码出的条码等于期望帧号；覆盖首帧、末帧、跨场景、随机与逆序 seek。
2. 子帧：开启运动模糊、素材静止、镜头移动时，各子帧取到的是同一源帧（通过页面内调试钩子读取，而不是从混合后的图像推断）。
3. 累积：已知色块的加权平均与理论值的误差 ≤ 1/255。
4. 编码链路：完整导出成 H.264 后，再解码读取条码，确认仍可读。
预算（参考机器，4 worker，含编码）：录屏场景的导出吞吐不低于纯页面场景的 50%；每个 worker 内存峰值 ≤ 2 GiB；冷启动到首帧 ≤ 10 秒。
失败时：先区分瓶颈在加载、解码还是合成；再试 WebCodecs `VideoDecoder`；都不行再开 Revideo 评估。

**0c · Playwright 录屏。**
用 `page.screencast.start({ onFrame, size: { width: 1920, height: 1080 }, quality })` 录制本地测试页（CSS 动画、滚动、点击）。
`size` 必须显式设置，并检查实际 JPEG 尺寸（默认上限 800×800）。不用 `path` 方式，因为当前发布版 1.63 的 webm 固定 25fps，`fps` 选项要到 1.64。
测试页在每次点击时于画面内显示可见标记（帧内条码），用来独立验证对齐。事件记录 DOM `pointerdown` 时刻（`performance.timeOrigin + event.timeStamp`），与帧时间戳同一时钟。
退出条件：
- 动画期间帧间隔中位数 ≤ 34 ms，p95 ≤ 50 ms，最长停顿 ≤ 100 ms（画面静止时浏览器不出帧，这段不计入）；
- 实际 JPEG 尺寸等于请求尺寸，quality ≥ 90 时 14 px 文字可读（人眼抽查 + 记录样张）；
- 重采样为 30fps 后，事件与帧内可见标记的偏差 ≤ 1 帧。
失败时：这是录制问题，不是渲染器问题。备选录制方式（CDP screencast 直接调用、系统录屏）单独评估，不影响 0b 的结论。

**0d · macOS 实机。**
协作者在 macOS 上运行 `spikes/` 中的短样片（含 WebGL 背景与录屏素材），记录 GPU 后端、扩展可用性、帧率与画面是否正常。
实验脚本按平台选择 ANGLE 后端（Windows 用 `d3d11`，其他平台交给浏览器默认），并在启动时检查 WebGL2、`EXT_color_buffer_float` 与 framebuffer 完整性，缺失即报错。
0d 可与阶段 1 并行，但阶段 1 合并前必须完成。

**决策门。**
0a、0b、0c 通过 → 保留自研渲染器，进入阶段 1。0b 失败 → 带数据重新讨论渲染器。0c 失败 → 只更换录制方式。0d 暴露的平台问题进入阶段 1 修复清单。

### 阶段 1 · 分层重构（骨架改动，阶段 0 后再确认）

分三个 PR，严格区分"纯搬迁"和"行为变化"。

**1a · 纯搬迁，逐像素一致。**
目录：

```
engine/          与片子无关：时间、帧管线、绘图原语、WebGL、导出、校验
styles/<id>/     风格包
films/<id>/      一部片子：film.ts、scenes/、score.py
```

依赖方向 `films → styles → engine`，用 lint 规则或导入检查强制。
风格包接管：色板（语义名）、字体、纸面与背景着色器、版式网格、章节装饰、字幕位置与样式、调色参数、转场、动效。
场景通过 `SceneContext` 访问风格与原语，不直接 import 引擎内部，也不直接调用 `paper()`、`glDraw(3)`。
契约：`FilmSpec`、`SceneSpec`（Zod）。
退出条件：0a 的全部检查帧，加每秒一帧的全片抽样，与 `421b107` 的 PNG 逐像素一致；导入检查通过。

**1b · 时间轴与音频（行为变化，单独记录）。**
- 场景只声明时长，起点由解析得出；tail 从 `sources.len` 中拆出，成为 film 字段；输出 `timeline.json`。
- 起点从 `192.60000000000002` 变为 `192.6` 等浮点边界修正会改变个别帧的场景归属（已知第 5778 帧），逐一列出受影响的帧并人工确认。
- `music.py` 读取 `timeline.json` 中的场景区间，编曲以"场景 + 场景内小节"定位，而不是全局小节号。
- `music.py` 输出经过最终处理（loudnorm 两遍 + limiter）的 WAV 母版；预览 MP3 与成片 AAC 都由它派生。
- `just music` 依赖 `just cues`。
退出条件：总时长不变（202 秒）；除已列出的边界帧外逐像素一致；母版 WAV 的时长、积分响度（−16 LUFS ±0.5）与真峰值（≤ −1.5 dBTP）符合目标。

**1c · 导出可靠性、字体、平台（行为变化）。**
- 导出：作业隔离的临时文件；改名前检查帧数、时长、音轨；去掉 `-shortest`，音频短于视频即失败；无音频时必须显式 `--noaudio`；
  worker 启动失败、编码器失败、中断信号都会回收全部子进程；整个作业有截止时间。
- 色彩：输出显式标记 BT.709 / limited range。
- 平台：ANGLE 后端按平台选择；启动时检查 GPU 能力；着色器编译失败即报错。
- 字体：OFL 字体随仓库分发；按 film 声明的字符集子集化；用 fonttools 校验实际文本（字幕、场景文字、动态数字的字符集）的字形覆盖；
  删除"15 秒后强制就绪"的逻辑，字体缺失、损坏、缺字、超时都让导出失败。
- README 修正"预览与导出逐帧一致"的说法（预览 1 个子帧，导出 3 个）。
退出条件：失败用例全部按预期失败（短音频、缺音频、worker 启动失败、编码器失败、重复运行、缺字）；Windows 与 macOS 都能预览和导出短样片；
字体替换后的样张经人眼验收。

**风格解耦验收（1a–1c 完成后）。**
第二套风格包（由 `nebula` 背景扩展而来，色板、字体、版式、转场均不同），用页面场景与全幅背景场景两类代表场景验证：
不改场景代码即可切换；`validate` 无文字溢出；人眼确认两套风格可明显区分。

### 阶段 2 · demo 片基础能力

分三个 PR。

**2a · 录屏合成。**
契约：`CaptureAsset`（帧序列、帧时间戳、viewport、DPR、`events.jsonl`）。
时间映射：录制时间 → 素材时间（含裁剪、删除空闲段、变速）→ 影片时间；坐标映射：viewport × DPR → 素材像素 → 输出画面（含镜头缩放平移）。
事件随这些变换同步变换。BrowserDemo 场景：镜头规划（缩放、平移、跟随）、合成光标、点击波纹、窗口外观，全部由风格包提供参数。
退出条件：用 0c 的测试页录制，最终画面中合成光标与页面内可见标记的偏差 ≤ 4 px、≤ 1 帧；BrowserDemo 在两套风格下都通过风格解耦验收。

**2b · 旁白与时间轴。**
契约：`Script`（分段、稳定 token ID、读法规范化映射）、`Alignment`（token ID → 起止时刻，含所属分段的音频偏移）。
TTS 适配层：本地 Kokoro（英文）与一个云端后端；时间戳优先取 TTS 自带的，没有则对已知文本做强制对齐（WhisperX）。
锚点引用 token ID，不引用字符串。数字、金额等无法得到词级时间时，降级为句级并输出 warning；被引用的锚点缺失则报 error。
场景时长 = `max(旁白 + 留白, 必须展示的素材段)`。音乐适配：垫乐循环、切点落在最近的小节线、旁白时压低音乐。
退出条件：包含版本号、金额、重复术语的测试文案全部得到有效锚点或明确降级；旁白 2 秒而素材 5 秒的用例按规则延长场景，结果不被截掉。

**2c · 给 agent 的命令。**
`validate`（schema、时间轴、cue、字体覆盖、素材、token 引用、文字溢出、安全区、对比度）、`thumbs`（每场景若干帧的缩略图拼板）、
`render-scene`、`render-range`，均输出 JSON。素材清单：每个非代码素材记录来源、许可证、sha256、生成模型与种子。
契约：`Brief`、`FilmPlan`（Zod，可导出 JSON Schema）。
退出条件：每条校验规则至少有一个会触发它的失败用例；agent 只用这些命令就能完成"改场景 → 看拼板 → 修正"的一轮。

### 阶段 3 · agent 接口与实战

- AGENTS.md（Claude 与 Codex 共用；CLAUDE.md 只指向它）：分层约定、契约、如何加场景、风格规则、验收清单。
- 项目 skill：brief → film plan → 场景 → 渲染自检 → 修改。
- 实战：一个真实 hackathon 项目，60–90 秒，含录屏、旁白、配乐、字幕。
退出条件：
- `engine/` 无改动（`git diff` 为空）；
- 仓库保留可重跑的全过程产物：`brief.json → film-plan.json → scenes/ → thumbs → validate 报告 → 修改记录`；
- 从 `brief.json` 重新运行，能得到通过 `validate` 的成片。

## 风险

| 风险 | 缓解 |
|---|---|
| 录屏嵌入的吞吐或内存不可接受 | 0b 带预算实测；备选 WebCodecs，再备选 Revideo |
| Playwright 录屏帧率不稳 | 0c 带阈值实测；失败只换录制方式 |
| 重构引入不可见的画面变化 | 无损 PNG 逐像素回归；纯搬迁与行为变化分 PR |
| 跨平台字体与 GPU 差异 | 字体随仓库并校验覆盖；按平台选后端；0d 实机；正式成片在固定环境渲染 |
| 模型与素材许可证 | 素材清单必填许可证；默认只用许可明确的模型 |
| 引擎越长越杂 | 依赖方向强制；新原语进 engine 前必须有两部片子用到 |
